## Top 5 Most Dangerous Gaps

Ranked by likelihood of explaining "plugin is unstable in a specific DAW":

1. **#7 — Shared singletons across "instances" (AU sandboxing divergence).** Every track in the harness shares one `PluginFactory`, `InstanceRegistry`, `ShaderRegistry`, `MemoryBudgetManager` (`PluginFactory.cpp:40-48`, `TestTrack.cpp:47-49`). Under Logic AU each plugin is a separate process — the registry is per-process and cross-instance discovery/dedup does not work the way the harness "proves" it does. Any feature that leans on `InstanceRegistry` cross-talk is effectively untested for the production sandbox model. This is the single biggest "works in harness, broken in Logic" vector.

2. **#4 + #14 combined — Audio-thread `prepareToPlay` and out-of-order `setStateInformation`.** `deferRegistration` has an explicit audio-thread branch (`PluginProcessor.cpp:134-137`) and `setStateInformation` snapshots `currentSampleRate_` at call time (`PluginProcessorState.cpp:81`). Neither branch is exercised. Pro Tools and Reaper both hit these in production. A regression in `callAsync` ordering or the sample-rate snapshot would ship undetected and manifest as "plugin loads at wrong rate then crashes on first block" in those DAWs only.

3. **#1 — Sample-rate change mid-session.** `prepareToPlay` is invoked exactly once per track (`TestTrack.cpp:76`). In production, users open a session at 44.1k, swap interfaces, and get called again at 48k. Everywhere `currentSampleRate_` is read on the audio thread (`PluginProcessor.cpp:228,242,258`) or cached in the editor (`PluginEditor.cpp:327`) could be stale during the reconfigure window. This is the classic "only crashes the second time the user plays the session" DAW bug.

4. **#5 + #9 — `getStateInformation` on the audio thread during active playback.** The RT-safe tryLock fast path (`PluginProcessorState.cpp:22-31`) has literally zero callers in the harness. Pro Tools autosave fires this exact path. If the tryLock is always uncontended in the harness (which it is, because no audio thread ever calls it), a regression that introduces a blocking allocation is invisible until a Pro Tools user hits save mid-playback.

5. **#8 — Editor detach/reattach without destroying the processor.** Harness's `hideEditor` destroys the editor (`TestTrack.cpp:120-128`) and `showEditor` creates a new one — a clean teardown. DAWs commonly reparent the editor component (hide window, keep component alive, show later) which drives `parentHierarchyChanged` (`PluginEditor.cpp:247-256`) with non-null/null transitions that the harness never produces. OpenGL context re-attach, `testServer_` double-start (`PluginEditor.cpp:120-123` unconditionally binds port 8765), and `renderCoordinator_->detach()` idempotency all live in this blind spot.
